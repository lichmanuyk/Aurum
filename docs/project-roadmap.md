# План долгосрочного форка Aurum

Статус на 2026-09-24. Основан на исходных фазах проекта; перенос конкретных
пользовательских данных не означает, что универсальный механизм миграции завершён.

| Фаза | Статус | Результат / следующий шаг |
| --- | --- | --- |
| 0. Аудит и архитектура | Выполнено | Модель данных и денежные зависимости описаны. |
| 1. Основа мультивалютности | Выполнено | Native currencies, исторические FX, точность, миграции, backup. |
| 2. Мультивалютность во всех разделах | Реализовано; регрессионное закрепление | Счета, отчёты, капитал, бюджеты, цели, крипта и предупреждения используют валюты. |
| 3. Начальные остатки и корректировки | Выполнено | Opening/reconciliation/migration не загрязняют доходы и расходы. |
| 4. Миграция Monefy | Основной путь выполнен; расширение частично | Переводы, исходные строки и сверка сохранены. Универсальная классификация целей/инвестиций и категорий в теги остаётся отдельной задачей. |
| 5. Финальный перенос | Выполнен для предоставленного снимка | Остатки и отчёты сверены, криптоостатки перенесены. Для постоянной эксплуатации ещё нужны регулярные бэкапы и наблюдение за свежестью котировок. |
| Закрепление качества | Текущий этап | Регрессии денежных инвариантов, отказов, конкурентных действий и основных экранов; автоматический прогон. |
| 6. Движение капитала | Не начато | Связать реальные деньги на счетах с покупкой/продажей/переводом активов без двойного учёта и ложных расходов. |
| 7. PR в upstream | Позже, по отдельному решению | Выделить универсальные части из персонального форка. |

## Порядок следующих работ

1. Закрепить текущую реализацию тестами и отдельным PR в `personal`.
2. Настроить постоянные резервные копии и восстановление; затем отображение
   свежести котировок и приведение новых переводов интерфейса к общему словарю.
3. Спроектировать Capital Movements на реальных сценариях пользователя:
   покупка/продажа крипты или другого актива, комиссии, вывод денег на счёт.
4. При необходимости связать цели с резервированием реальных денег. Сейчас
   прогресс цели сам по себе не перемещает деньги и не создаёт новый капитал.
5. Добавить исторические криптосделки, когда доступны выгрузки; заменить
   начальные остатки без удвоения количества и восстановить достоверную себестоимость.
6. Опционально подготовить отдельные небольшие upstream PR.

Контекст от пользователя: для бэкапов — место хранения и срок хранения;
для Capital Movements — 2–3 примера желаемых действий; для истории крипты —
выгрузки сделок. Эти сведения не нужны для текущих синтетических тестов.

## Правило Git

`upstream/main → main → personal → отдельная feature-ветка → PR → personal`.
Каждое исправление регрессии сопровождается проверкой, которая воспроизводит
проблему. Большие независимые улучшения не накапливаются в одной ветке.
