# Работа над персональным форком

`docs/project-roadmap.md` — общий план и статус. `docs/tasks/` — отдельные
задания с критериями приёмки. Реализацию ведёт Claude Code по заданию,
переданному пользователем; Codex ведёт план, готовит задания и проверяет
результат. Пользователь сообщает, когда Claude Code закончил, и принимает
решения, для которых нужны его предпочтения или личные данные.

## Один цикл

1. Codex выбирает следующий ограниченный пункт плана, проверяет текущий код,
   записывает цель, границы, инварианты и критерии приёмки в `docs/tasks/` и
   выдаёт пользователю готовый промпт для Claude Code.
2. Claude Code работает в отдельной ветке от актуальной `personal`: реализует
   только этот пункт, проверяет на синтетических данных, запускает нужные
   серверные, клиентские и браузерные тесты, открывает PR в `personal`.
3. Claude Code сообщает ссылку на PR, краткий список изменений, результаты
   проверок и оставшиеся ограничения. Не объявляет задачу завершённой, если
   тесты или CI не прошли.
4. Пользователь передаёт Codex ссылку на PR. Codex сверяет результат с
   заданием, смотрит diff и CI, при необходимости просит исправления через
   новый промпт. Затем обновляет статус плана и готовит следующее задание.

Если изменение требует настоящих финансовых данных, сначала реализуется и
проверяется универсальный механизм на синтетических примерах. Отдельное
применение к постоянной базе согласуется по конкретному набору изменений;
перед ним обязательны резервная копия и сверка после. Ни агент, ни тесты не
должны использовать личную базу `aurum-personal` как тестовую.

## Правила для задания и PR

- Сохранять `main` для upstream; рабочая схема — отдельная ветка → PR →
  `personal`. Не коммитить в `personal` напрямую и не смешивать независимые
  пункты в одном PR.
- В задании формулировать наблюдаемое поведение и запреты на нарушение
  финансовой математики; способ реализации агент выбирает после чтения кода.
- Не менять реальные счета, операции, настройки, ключи, бэкапы и Docker в
  ходе реализации. Продакшен на порту 3003 — не тестовый стенд.
- Проверять совместимость старых резервных копий при изменении схемы данных.
  Добавлять миграцию, тест восстановления и обновлять версию формата только
  если изменение действительно требует этого.
- UI проверять браузерным сценарием на отдельном стеке, включая узкий экран.
  Новые тексты поддерживать на русском и английском. В PR перечислять
  команды и фактические результаты проверок; ждать зелёный CI.
- Не удалять существующие комментарии без замены актуальными. Не включать в
  diff личные данные, секреты или скриншоты с ними.

Задание считается закрытым после проверки Codex и фиксации результата в
плане. Самоотчёт исполнителя — вход для проверки, а не доказательство её
успеха.

После приёмки функционального PR Codex обновляет docs/release-notes.md: 1–2 предложения о поведении и где попробовать. Слияние и проверенное развёртывание отмечаются отдельно.
