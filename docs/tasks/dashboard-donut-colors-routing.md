# Задание 08: цвета пончика расходов и линия вокруг него

Статус: принято, PR #46 слит в personal 2026-09-26. Исправления 94c5ffa проверены; после синхронизации с personal все три CI на cd87153 зелёные. Чистая геометрия отделена от React, SVG не обрезает линию. Домашнее развёртывание ещё не проверено. Источник: [дополнение плана](../project-roadmap.md#дополнение-к-плану-от-2026-09-26).

## Результат

На дашборде пончик расходов использует различимые сплошные цвета как распределение крипты, без штриховки. Цветной маркер каждой строки совпадает с её сектором, включая «Прочее». Это новое предпочтение пользователя после PR #42.

Активная строка на широком экране соединяется с серединой внешней дуги сектора аккуратной ломаной линией. От строки линия сначала выходит горизонтально на одинаковую длину для всех строк, затем идёт с углами по свободному пространству вокруг пончика. Она не проходит через кольцо, его отверстие, тексты/суммы/кнопки; касается внешней окружности только конечной точкой. На телефоне оставить согласованную подсветку без тесной линии.

## Границы

- Ограничиться SpendingByCategoryCard и необходимой переиспользуемой геометрией/палитрой. Крипто-пончики и полоса капитала сохраняют нынешнее поведение; если меняется общий helper, проверить их регрессии.
- Цвета только для представления графика, не записывать их в категории/БД. Использовать существующую палитру приложения и стабильный ключ категории; одни и те же категории не должны менять цвет просто от сортировки/переключения валюты. Коллизии разрешать детерминированно для текущего набора. Проверить максимальные 8 секторов и «Прочее».
- Не менять суммы, проценты, группировку, FX, операции, backup. Подсветка, pin, Escape, клавиатура, настоящее касание и актуальные суммы модалки из PR #42/#44 сохраняются.
- Реальную геометрию Recharts (margin, paddingAngle, радиус) сохранить. Маршрут может идти по нескольким внешним коридорам: окружить пончик ограничивающим контуром с отступом и вывести конечный отрезок к нужной внешней дуге, не пересекающий круг. Не приближать маршрут прямой хордой.
- Исследовать фактическую компоновку и выбрать минимальную ясную реализацию; без универсального маршрутизатора диаграмм. SVG-слой не перехватывает клики.
- RU/EN тексты при необходимости, комментарии сохранить. Только изолированный тестовый стенд, без 3003 и aurum-personal.

## Приёмка

1. Пять одноцветных исходных категорий и максимальные 8 секторов: все реальные заливки сплошные и различимы, маркеры совпадают, до hover. Проверить стабильность цвета при смене порядка/валюты, «Прочее», один сектор, пустое состояние.
2. Все направления дуги, особенно дальняя от списка половина; маленький сектор и неравные доли. Автоматически проверять каждый отрезок маршрута на пересечение круга с учётом допустимой конечной точки, а не только bounding box. Проверить конечную точку у середины реальной внешней дуги и равную длину первого горизонтального участка.
3. Визуально 1440/375px, длинные строки: линия читаема, не проходит через пончик/тексты, без переполнения. Hover в обе стороны, Enter/Space/Escape, hasTouch + tap, смена периода/валюты с открытой детализацией.
4. Обновить устаревшие проверки узоров только на дашборде, заменив проверками нового поведения; не ослаблять крипто-проверки. Сборка, unit-тесты и полный изолированный Playwright; зелёный GitHub CI.
5. Новая ветка от актуальной origin/personal; PR в personal. Не сливать/разворачивать. Отчёт со ссылкой, SHA, проверками и снимками синтетических данных. docs/release-notes.md и статус задачи обновляет Codex после приёмки.
