# Задание 07: сортировка и выделение капитала

Статус: завершено, PR #44 слит в personal 2026-09-26. Проверен be72f31: все три CI зелёные; клиентские тесты 133, изолированный Playwright 63. Домашнее развёртывание ещё не проверено. Источник: [общий план](../project-roadmap.md), заметка «Капитал».

## Результат

В «Капитале» распределение классов активов показывается по убыванию стоимости: сегменты горизонтальной полосы, легенда и строки используют один порядок. Наведение/фокус на строку выделяет соответствующий сегмент и приглушает остальные; взаимодействие с сегментом выделяет строку. Закрепление нажатием, повторное нажатие и Escape работают как в задании 06. На телефоне использовать настоящее касание. Полосу не превращать в пончик, соединительные линии ей не нужны.

«Мои активы» также сортируются по убыванию стоимости, сравнимой в выбранной валюте капитала. Нельзя сравнивать напрямую числа EUR, USD и PLN. Показать эквивалент, объясняющий порядок, сохранив доступность исходной суммы и валюты. При одинаковой стоимости — устойчивый порядок по имени и id.

Распределение содержит классы, а «Мои активы» — отдельные ручные активы: это разные уровни. Подсветка в этой задаче связывает строки классов с сегментами классов. Не выдавать весь сегмент класса за один предмет; отдельный график всех счетов/монет/предметов — вне рамок.

## Границы и ориентиры

- Проверить AssetAllocationCard, AssetsTable, NetWorthPage, useAssets, API /assets и net_worth_service. Переиспользовать chartSelection из PR #42, если подходит.
- Сортировать копии данных; не менять итоги, доли, классы, риск, роли капитала или порядок API без явного запроса.
- Эквивалент ручного актива должен совпадать с его вкладом в текущую сводку капитала. Исследовать реальный путь FX и дату конвертации в сводке; использовать тот же механизм, без нового клиентского курса или самостоятельного определения «сегодня».
- При необходимости добавить совместимый read-only параметр/поля API для эквивалента. Нативные current_value, currency, оценка, редактирование, денежный поток и расчёт доходности сохраняют прежнюю семантику. Без запроса новой валюты старые потребители работают как раньше.
- Отсутствие курса — явная ошибка/недоступность, не 0 или 1:1; отсутствие оценки не притворяется реальным нулём. Определить явный порядок неоценённых строк, не теряя их.
- Устойчивые ключи для выделения; обновление данных/валюты не сохраняет старые суммы. При исчезновении выбранной группы выделение сбрасывается.
- Кнопки изменения, удаления и покупки/продажи продолжают работать независимо от выделения. Без вложенных кнопок и aria-pressed на строке таблицы; тонкие сегменты должны иметь доступный способ выбора через список.
- Только синтетические данные и отдельный Docker-стенд. Не менять порт 3003, aurum-personal, реальные данные и расписания. Схема/backup не должны меняться ради вычисляемого эквивалента. Новые тексты RU/EN, комментарии сохранить.

## Приёмка

1. Разные валюты, при которых сортировка нативных чисел дала бы неверный порядок; равные значения; ноль; отсутствующая оценка; отсутствующий FX. Эквиваленты сверены с текущей сводкой, итог капитала до/после одинаков.
2. Согласованный порядок полосы/легенды/строк. Hover в обе стороны, клавиатура Enter/Space/Escape, настоящее hasTouch + tap на 375 px; повторный тап снимает выделение полностью.
3. Переключение валюты и обновление данных сохраняет только актуальные значения; исчезновение группы не оставляет выделения. Проверить независимость финансовых кнопок.
4. Снимки 1440/375 px без переполнения; достаточная видимость приглушённых элементов, доступные подписи. Не ослаблять старые проверки.
5. Нужные backend/unit-тесты, сборка и полный изолированный Playwright; GitHub CI зелёный. Новая ветка от актуальной origin/personal, PR в personal. Не сливать и не развёртывать. Отчёт: ссылка, SHA, результаты, ограничения, фактический способ и дата FX для сравнения.
