# Задание 01: валюта отображения в настройках

Статус: готово к передаче Claude Code; реализация не начата.
Источник: [общий план](../project-roadmap.md), «Валюты разделов».

## Проблема

PLN остаётся основной валютой учёта, но капитал, криптовалюту и месячный
дашборд пользователь хочет постоянно видеть преимущественно в USD/EUR.
Сейчас эти три страницы используют общий крупный переключатель и одно
значение в `localStorage`. Выбранная валюта видна только в этом браузере;
она не настраивается отдельно по разделам.

## Результат этого PR

- В настройках можно выбрать общую валюту **отображения сводок** из
  PLN/USD/EUR и отдельно для дашборда, капитала и криптовалюты выбрать
  «как в общей настройке» либо PLN/USD/EUR. Это не меняет основную валюту
  учёта, валюты счетов/операций/целей/бюджетов и фактический курс перевода.
- Настройки сохраняются на сервере и переживают обновление страницы, новый
  браузер и перезапуск приложения. До первого выбора действуют нынешние
  значения по умолчанию; существующее локальное значение можно перенести
  один раз без неожиданной смены валюты у пользователя. Продумать и
  протестировать поведение при конфликте локального и серверного значения.
- На этих трёх страницах убрать крупную панель выбора. В заголовке страницы
  показывать компактное действие для временного просмотра в основной валюте
  учёта **только если** установленная валюта раздела от неё отличается.
  Повторное действие возвращает настроенную валюту; настройку на сервере
  оно не меняет. Действие не показывать на других страницах. UI должен
  работать на телефоне и с клавиатуры.
- Все денежные итоги, графики, легенды, подсказки и запросы к API на каждой
  из трёх страниц используют одну выбранную валюту. Исходные количества
  криптовалют и нативные суммы счетов остаются неизменными. При недостающем
  курсе сохраняется явная ошибка, а не 0 или фиктивный курс 1:1.

## Границы

В этом PR не добавлять обзор текущих курсов, не расширять переключение на
«Движение денег»/«Отчёты», не менять модель FX и не трогать реальные данные.
Эти разделы — следующий самостоятельный PR после проверки общей схемы
настроек. Не создавать новый глобальный курс из пользовательского перевода.

## Критерии приёмки

1. Синтетический сценарий: общая USD, капитал EUR, крипта наследует USD,
   дашборд PLN. После перезагрузки и в новом браузере выбор тот же;
   временный просмотр в PLN не меняет сохранённые настройки.
2. Изменение основной валюты учёта не переписывает исходные записи;
   наследующие разделы следуют общей валюте отображения, явные overrides
   сохраняются. Два разных перевода в один день не меняют друг другу курс.
3. Серверные тесты проверяют валидацию, сохранение и backup roundtrip новых
   полей, включая импорт старой копии. Клиентские тесты проверяют
   наследование/override/временный просмотр; Playwright — настройки и три
   страницы на десктопе и узком экране в одноразовом стеке.
4. Проходят backend pytest, frontend build/Vitest, подходящие E2E и GitHub CI.
   В diff нет личных данных; PR описывает точный результат и ограничения.
