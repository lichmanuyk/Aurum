# Задание 09: курсы за период и мини-графики дашборда

Статус: готово к передаче Claude Code. Источник: [общий план](../project-roadmap.md), дополнение от 2026-09-26. Продолжение PR #36.

## Результат

Карточка курсов реагирует на выбранный период дашборда и показывает четыре явно подписанные пары:
- 1 USD = X PLN; 1 EUR = X PLN;
- 1 USD = X BYN; 1 USD = X RUB.

Пары фиксированы по предпочтению пользователя, независимо от основной валюты/валюты сводки. Для «Всё время» и текущего месяца основная цифра — последняя доступная официальная котировка. Для прошлого месяца и целого прошлого года — средняя ежедневная котировка периода. Для текущего года с «Все месяцы» — средняя с начала года до серверного сегодня, с подписью «с начала года». Будущие даты не получают котировок. Сохранить совместимость существующего GET /fx-rates/overview для старых потребителей: новый контракт оформить отдельным read-only endpoint либо явным новым режимом запроса.

Справа в каждой карточке мини-график с мягким затуханием к тексту. Для среднего график охватывает тот же период; для текущего курса — последние 30 календарных дней включительно по серверное сегодня. Рост конечной отображаемой котировки относительно начальной — зелёный, снижение — красный, равенство — нейтральный. Это движение указанной цены, не доходность пользователя; рост USD/BYN означает укрепление доллара к BYN, не рост стоимости BYN.

## Расчёт и достоверность

- Сервер определяет период через те же правила календарных границ, что сводка дашборда (_resolve_bounds). Не вычислять границы/«сегодня» браузером. Обзор работает и при ошибке денежных итогов — отсутствие отчётного FX не должно скрывать справочную карточку.
- Использовать только сохранённые строки source NBP:...; manual-строки не являются официальными. GET ничего не записывает и не обращается к NBP. Реальные обмены/исторические суммы не меняются.
- Для каждого календарного дня использовать последнюю доступную официальную публикацию каждой нужной пары к PLN, не позже дня, с существующим пределом давности 7 дней включительно. Для выходных переносить последнее опубликованное значение; BYN/RUB из недельной таблицы B также переносятся по дням.
- Кросс-курс USD/BYN или USD/RUB строить из независимых последних официальных USD/PLN и BYN/PLN или RUB/PLN на этот день: не требовать совпадения дат таблиц A/B и не застывать на недельном курсе USD. Сохранять фактические даты/источники обеих ног; понятная дата подписи не должна выдавать старую ногу B за сегодняшнюю. Новая логика только для обзора; глобальный FXConverter финансовых отчётов не менять.
- Среднее — арифметическое ежедневных значений в отображаемом направлении, с одинаковым весом каждого календарного дня. Инверсию/кросс вычислять ДО усреднения. Decimal достаточной точности, округление только для вывода, не до среднего.
- Ответ содержит режим latest/average, фактические серверные границы, пары base/quote, значение/null, публикационные даты/источники, дневной ряд и покрытие (ожидаемые/доступные дни). Отсутствующие точки null, не 0/1:1. При неполном среднем основная цифра недоступна с ясным указанием неполноты; не показывать частичное среднее как полное.
- График не соединяет разрывы выдуманными точками. При неполном ряде не показывать зелёный/красный «результат периода» по случайным внутренним концам. Для полного ряда цвет определяется первым/последним неокруглённым значением; для отсутствия/единственной точки нейтральный.
- Историю до доступности NBP (2002-01-02) не выдумывать. Будущие/несовместимые параметры явно отклонять. Текущий месяц/год может быть укорочен только по серверное сегодня.

## Загрузка истории

Автообновление /nbp/latest оставляет прежний короткий набор. Не включать RUB/BYN без реального использования в import_plan/coverage финансовых данных ради обзора.

Когда сохранённого ряда не хватает, карточка показывает «Недостаточно истории» и явное действие «Загрузить курсы за период». Переиспользовать POST /fx-rates/nbp и существующий NBPImport: ограниченные интервалы до 93 дней, валюты USD/EUR/BYN/RUB, плюс до 7 дней перед началом для первой доступной публикации (не раньше 2002-01-02). Это явное действие, не новая сеть при каждом просмотре/переключении.

Загрузка показывает ход/ошибку и повтор только недостающих интервалов, не создаёт многолетний запрос для «Всё время» (в этом режиме лишь окно графика 30 дней). Не перезаписывать ручные FX, не расширять обязательную полноту отчётов. Обработка 404/429/5xx через существующий путь; нет параллельного шторма запросов. Существующие сохранённые финансовые записи не импортировать/не менять.

## UI и границы

- FxRateOverviewCard и DashboardPage, quote_status_service, fx routes, nbp_service, тесты overview — ориентиры, перед изменением прочитать реальные связи.
- queryKey включает период; смена периода не оставляет старое среднее с новой подписью. При смене настроек валюты сводки фиксированные пары карточки сохраняются.
- Сохранить loadError/retry, различать ошибку запроса и честную неполноту. Даты/источник и latest/average видны; доступные подписи значений/графика RU/EN. На 375px без переполнения, значения читаются независимо от фона мини-графика.
- Без изменения app_settings, схемы/backup, крипты, операций или валют счетов. Не строить отдельную торговую страницу или разложение прибыли рынка в этом PR.
- Только синтетические данные и изолированный стенд; 3003/aurum-personal не трогать. Существующие комментарии сохранять/актуализировать.

## Приёмка

1. Все 4 направления, инверсия до среднего, независимые даты A/B: изменение USD между недельными публикациями B меняет правильный кросс. Среднее по календарным дням (выходные и начало периода с публикацией ранее), текущий месяц/latest, текущий год/YTD, прошлые месяцы/годы, границы около смены дня.
2. Слишком старая нога, manual-конфликт, пропущенные точки и неполное покрытие явно недоступны; соседние доступные пары остаются. GET без запросов к источнику и записей. Числа денежных отчётов и два обмена одного дня с разными фактическими курсами неизменны.
3. Загрузка по явному действию в нескольких 93-дневных интервалах, предварительные 7 дней, отсутствие запросов при простой смене периода, отсутствие нового RUB в финансовом coverage; сетевые ошибки/повтор без дублирования/перезаписи ручных значений.
4. Unit-тесты математики/метаданных/цвета тренда и backend-контракта; Playwright desktop/375px: переключение all/year/month, актуальные подписи/данные, ошибка/повтор, неполнота/явная загрузка. Источник сети мокается, тест не зависит от живого NBP.
5. Сборка, необходимые серверные/клиентские тесты, полный изолированный Playwright и GitHub CI зелёные. Новая ветка от origin/personal, PR в personal, без слияния/развёртывания. Отчёт: ссылка, SHA, проверки, снимки синтетики, ограничения метода. План и release-notes закрывает Codex после приёмки.
